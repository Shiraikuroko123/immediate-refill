02 / the problem

A free slot changes the clock.

In parallel self-consistency, a finished reasoning path releases a slot. The usual instinct is to refill it immediately. That decision also changes the number of active paths in the batch, so it can change the next decoding step for every path still running.

The paper treats admission as a control problem with a hard launch quota. Every request consumes budget from the moment it starts, including paths canceled after an early vote certificate.

The question is therefore narrower than “does batching help?” It is whether an admissible scheduler should spend a newly available slot now, given the current vote information and the measured width-dependent cost.

“

The fastest schedule is determined by the geometry of the decoding cost curve, not by the number of paths alone.

03 / mechanism

Admission is an information problem.

Index-based admission uses all returned votes, including votes from paths outside the completed prefix, while preserving the launch order.

The admission loop. Returned indices are part of the state.

01

Observe

Record every completed index and its vote, including out-of-order returns.

02

Bound

Compute F(S) = min(Q, |S| + P, M(S) + B) from the strongest consistent prefix.

03

Refill

Launch only the next admissible indices. Stop immediately once a strict certificate exists.

No future votes are used at decision time.

04 / theory

One curve decides the universal case.

In the zero-extra-budget regime, every valid schedule completes the same serial prefix. Only the occupancy profile changes.

THEOREM 1 · B = 0

Immediate refill is universally optimal over arbitrary panel sizes and quotas if and only if the width cost is discretely concave.

05 / evidence

Separate the mechanism from the headline.

The archive reveals where information helps. The device session tests whether the same claim survives real engine overhead.

200 GSM8K problems · 3,968-token fixed clock

Most replayed savings come from seeing votes outside the prefix.

Index-based admission changed 138 of 200 schedules. Compared with waiting for a contiguous prefix, it saved 8.71% per problem on average (median 0.14%). Summed latency fell by 18.72%, with two long problems contributing 67% of the total time saved.

The width-cost prediction survives the controlled timing test.

For fixed lengths (256, 128, 128), the measured cost curve predicted a 3.13% gain from delaying the third launch. The paired device median was 2.46%, with all blocks on the predicted side of zero.
