# 生成长度上限与实机调度节时

图中每一行对应一题，按实验开始前固定的 0–31 号顺序排列。左上方蓝色空心圆表示 384 token 上限，棕色三角表示 1,024 token 上限。每个点均为 \(100(1-T_{\mathrm{索引}}/T_{\mathrm{缓冲}})\)。同一个点的两个耗时取自同一道题、同一生成上限、相同路径长度与选票的两次 A800 运行。正数表示索引调度耗时较短。右上图的每个菱形表示同一道题在两个上限下的节时之差，单位为百分点。正值表示放宽上限后索引调度的相对优势增大。

下方的每个点取全部 32 道题的简单平均。横线是实验前约定的 95% 百分位数区间，以题为单位有放回配对抽样 20,000 次，随机种子为 3841024。下排各自放大横轴，展示均值和区间。两个上限各使用自身的缓冲调度时间作为分母。调高上限还可能改变总工作量、绝对耗时和最后的答案。[实验协议](../PROTOCOL.md) · [逐题记录](../device-results/questions.csv) · [汇总与绝对耗时](../device-results/summary.json)

上限为 384 时，题均节时为 0.86%（95% 区间 −0.33% 至 2.23%）。上限为 1,024 时，题均节时为 1.30%（0.33% 至 2.39%）。逐题相减后，放宽上限使平均节时增加 0.44 个百分点，区间为 −0.79 至 1.84 个百分点。该区间跨零，放宽生成上限的效果仍不确定。

从项目根目录用已记录的 Python、Matplotlib 和 NumPy 环境运行下列命令。程序要求正式汇总包含全部 32 题、160 次运行和完整的题号集合，并核对每道题的差值及三个题均估计。输出包括可缩放 PDF 和 PNG。
