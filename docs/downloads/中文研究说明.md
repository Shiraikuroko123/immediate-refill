# 固定一批推理路径，最早何时能安全启动下一条？

给同一道题预先分配 8 个随机种子，各自产生一条推理路径，最后选择得票最多的答案。生成 5 个相同答案就足以锁定结果，剩下 3 条无论怎么投都无法改变胜者。逐条生成可以省下它们的成本，却让一定需要的路径排队；8 条一起启动则可能在知道胜者前已经生成了这些路径的大半内容。这里研究如何在保持串行实际使用的随机种子和生成 token 完全相同的条件下安排并发。

假设还有 \(R\) 条路径的答案未知，已完成答案中第一名比第二名多 \(g\) 票。一条路径完成时，最好也只能让分差多 1、未定票少 1。若再完成 \(k\) 条就能严格锁定，必须有 \(g+k>R-k\)。所以最少还要完成

\[
m=\min(R,\max(0,\lfloor(R-g)/2\rfloor+1)).
\]

开始时 \(R=8,g=0\)，可以启动 5 条。若第一张票投 A，更新后仍有 4 条在途，先不用补。如果随后 A、B 各获一票，当前分差回到 0，剩余 6 条，为了可能锁定至少需要再完成 4 条。这时在途只有 3 条，可以立即启动第 6 条。这样让确定用得上的路径更早进入解码。

**可以证明什么。** 假设种子顺序固定，路径的最终投票不随调度变化，每次只看已经完成的票，直到严格锁票或用尽预算才停止。在有空闲槽位时，把在途数补到 \(m\) 与容量两者的较小值，最终恰好生成串行算法会读取的同一个最短前缀。证明分两步。每新收一票，最少所需完成数至多减一，因此停机时没有在途任务。发出第 \(j\) 条路径前，当时已经发出但还未完成的条数又不足以锁票，因此任何相容的最终投票都需要读到第 \(j\) 条。固定的路径服务时间若不受同批大小影响，该策略启动每一条路径的时间都达到这类严格守住前缀的策略所允许的最早时间。[证明与穷举](../tracks/scheduling/checks/proof.md)

**与前人最接近在哪里。** 有限票数下的胜者锁定、窗口投票、提前取消、分支补发以及按不确定性停止都已有工作。这里涉及的细节是，要求每一种可能投票都保留原串行前缀时，已完成的票对允许启动的最大编号施加了什么约束。比较时必须允许对手在已经承诺处理的一批路径内连续填充空槽。只用每组都等齐的批处理作对照，会夸大新策略的贡献。[近期文献与代码审计](../tracks/voting/audit/COST.md)

**怎样独立检验公式。** 对一个小面板，可以把尚未完成的路径分别填成 A、B 或弃权，对每一种填法从头运行串行投票，再取最早的停止位置。这个位置就是所有填法都必需的最大编号。六条路径以内，2,822 个可到达的局面都与公式一致。进一步让调度器自己决定每个时刻发几条路径，也允许主动空出部分槽位。在至多四条路径、每条用一或两个时间单位的 33,018 种合法整数时间调度里，没有一种能比逐次补充更早发出某条路径。一般情形由定理证明。[独立穷举代码和复现说明](../tracks/scheduling/checks/ORACLE.md)

**第一轮数据说明什么。** 在公开 DeepSeek-8B BRUMO 轨迹生成的四个开发问题上，按相同的预定顺序构造了 240 个 8 路和 120 个 16 路面板。同工作量下，只有 4 个槽位时，与每批都等齐的策略相比少用了 16.06% 和 17.88% 的模型解码步。允许同一批连续填满槽位后，差距缩小为 1.22% 和 2.41%。槽位数等于面板大小时只剩 0.33% 和 0.80%。此前设定的 5% 主门槛没有通过；这决定了目前的稿件应解释收益在哪些条件下消失。[逐面板结果](../tracks/scheduling/runs/dev-01/rolling.csv)

**为什么研究过中途投票又换了机制。** MARS 会在推理尚未完成时提取暂定答案，再估计每条路径最终改票的概率。我们问过一个更细的问题：同一条路径改票可能威胁好几个对手，精确计算联合概率能否比简单上界更早停？在四道开发题上，360 个面板都没有提前。按每个新问题独立使用 32 条预热路径计算，8 路面板的预热加主路径已经达到全预算的 4.76 倍。题目的数学等价答案怎样规范化，也会明显影响改票率和拟合结果。这样的阴性结果支持先比较无需探测的确定性策略。[冷启动账本](../tracks/voting/audit/COST.md) · [跨题实验](../tracks/voting/transfer/README.md)

**面试时如何解释局限。** 回放使用现成答案和完成深度。在真实推理引擎里，不同批大小有不同的每步时间，预填充、内核选择和 KV 缓存也会影响时延，浮点运算甚至可能改变同一种子的采样结果。同答案和同前缀是给定相同潜在轨迹时的定理。题目是泛化的统计单位，同一题拆成许多面板不能代替更多独立题目。因此我们在两种真实 GPU 上分别测量自然生成与固定工作量的完成时间。投票一致性衡量能否复现同一决策，答案正确率还取决于模型本身。

**开发、验证和最终测试给出了不同幅度的结果。** 另外十个 BRUMO 问题中，234 条轨迹的末次探测没有给出真实生成长度。我们对固定版本的原文件逐页取数，核对了整文件哈希，并从逐 token 置信度数组的长度恢复终点。全部 240 个验证面板均进入分析。在四槽配置下，8 路和 16 路的模拟时间分别减少 4.81% 和 6.02%。最终测试用另一团队的 Qwen3-4B-Base 在 30 道 AIME 2024 题上的 960 条采样，按题等权的对应差距是 17.56% 和 19.62%。若改用一有空槽便开始下一条、锁票后可取消的策略，16 路四槽时，本方法在全题合计中反而多消耗了 11.7% 的 token。这个对照说明了“必须付出串行前缀的精确成本”这项假设的重要性。[完整验证](../tracks/validation/README.md) · [独立测试与原始结果](../tracks/heldout/README.md)

**同样多的 token，在真实机器上能提早多久完成？** Qwen2.5-1.5B-Instruct 在六道新的算术题上运行，每题重复三次。两种策略共用 H20 全面板记录的每条路径长度和选票，vLLM 实际生成相应数量的 token。每张卡上每种策略均完成 136 条路径，生成 20,661 个 token。与可连续补充已经承诺路径的滚动波次相比，四槽逐次补发的实机完成时间在 H20 上按题平均减少 10.78%（题级 bootstrap 95% 区间 7.08%–16.24%），在 A800 上减少 10.39%（6.41%–16.31%）。H20 使用 vLLM 0.7.3，A800 使用 0.8.5。自然生成时，H20 的 18 对测量有 4 对 token 数不同，A800 则有 6 对。在相同索引种子下，连续合批仍能改变文本甚至胜者。这是理论前提与实际部署之间最直接的差异。[实机汇总](../release/hardware/summary.json) · [324 条逐次记录](../release/hardware/panels.csv)

**独立核对算法。** 除 368,520 个调度样例外，我们用枚举所有相容的后续投票来直接计算最小必需前缀，核对了 2,822 个可达状态。在更小的面板上枚举了 33,018 种允许主动空闲的整数时间调度，未发现任何必需路径可以比推导的策略更早启动。该检查覆盖有限状态，任意面板大小的结论依赖正文证明。[直接枚举](../tracks/scheduling/checks/oracle.py)

**怎样自己复核。** 解压私有审阅包，按复现指南创建 Python 3.10 环境并安装依赖和 TeX。运行 `python release/reproduce.py --out my-reproduction`。从逐题 CSV 取出四槽、8 路数据，先对每道题计算两种策略的相对时间差，再对 30 道题求平均，核对 17.56%。实机段使用已收集的请求重新统计。重新生成原始 GPU 请求另需相应设备、公开权重与匹配的软件版本。[复现指南](../release/README.md) · [论文主张与证据](../release/CLAIMS.md) · [投稿要求](VENUE.md)

**三道可以动手回答的追问**

1. 为什么八条路径可以先发五条？起始时前四票即使全部一致，后四票仍能追平。无论数据集多容易，严格锁票都要至少五个完成事件。试把停止规则改为平票直接偏向某个固定标签，找出原公式不再最紧的状态。
2. 为什么把基线从等齐一批改为一有空位就送入已承诺的请求？两者都只在一个波次完成后重算还需要多少票。后者已经消除了硬性等齐造成的空槽，所以余下的差距才衡量“重新考虑该启动哪些路径”这一步。
3. 为什么不同算法可以在同一种子上写出不同答案？采样从模型的浮点 logits 得到，合批方式和运行内核会改变舍入误差。可以在实机日志中分别核对逐条 token 哈希、归一化选票、最终赢家和实际花费。四者回答不同的问题。

**复查中改正的一处数字。** 8 路、8 槽 AIME 配置的置信区间上界为 20.2492606%，保留一位小数应写为 20.2%。初稿误写为 20.3%，已按原始 CSV 更正。该项不属于四槽主结果。
