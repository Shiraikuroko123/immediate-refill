# Does a longer output budget change the value of indexed admission?

We will compare two output limits, 384 and 1,024 tokens, within the same GSM8K question, model, prompt and sampled set of paths. The earlier fixed-work device pilot used 384. An exploratory replay of 200 archived questions suggested that their long paths could account for some of the larger savings observed in that archive. The new study tests whether this pattern transfers to Qwen2.5-1.5B-Instruct on the A800.

Exclude all 200 questions in the archive analysis and all 16 questions in the previous GSM8K pilot (two appear in both). From the 1,105 remaining official GSM8K test questions rank the SHA-256 of `cap-transfer-v1/` followed by the exact UTF-8 question, and select the lowest 32. Keep every question. Use the same instruction to show reasoning briefly and end with a boxed integer as in the previous pilot. Use its checkpoint, engine version, BF16, 0.7 temperature, 0.95 top-p, four slots, absolute quota 14, maximum 16 paths and serial overrun allowance of one. Seed each path deterministically in a fresh namespace.

For each question first generate the full reference with a maximum of 1,024 new tokens. Construct the short reference by truncating each path at 384. In either condition assign abstention to paths reaching that condition's cap. Run both indexed and buffered admission on the device at each output limit with identical per-path fixed work and terminal votes within a pair. Each new question has five runs including its full reference. At question indices modulo four cycle the following orders, with A = short indexed, B = short buffered, C = long indexed and D = long buffered. Use A B D C, B C A D, C D B A and D A C B. Warm each timed panel and synchronize before reading elapsed time. Preserve individual engine events, errors and timed runs. Use a separate output directory for an interrupted attempt. Resume only when the source, input, model and engine setup match, recording which questions span sessions. Stop on a record-integrity failure.

Within cap \(c\) define \(s_{q,c}=1-T_{\rm indexed}/T_{\rm buffered}\). The single primary outcome is the mean paired interaction \(s_{q,1024}-s_{q,384}\), giving all 32 questions equal weight. Report a two-sided 95% paired question bootstrap interval with 20,000 draws and seed 3841024. A positive lower endpoint supports the directional hypothesis on this workload. If the interval crosses zero the evidence for that claim is inconclusive. A nonpositive upper endpoint refutes the positive direction at this precision. Separately assess practical utility at the long cap against the previous 2% criterion, a positive lower endpoint for its within-cap saving, and at least one changed dispatch. These intervals quantify variation across questions within this study. This is a pilot with a fixed sample size.

Report both caps' absolute wall times, steps, output tokens, number of dispatch differences, certificates and gold-answer agreement, and the fraction of paths reaching each cap. Retain unchanged schedules and slowdowns. Check the matched-path replay against engine dispatch and timing. Extra model work at the larger cap belongs in the comparison. If the interaction and dispatch evidence warrant a systems claim, next replicate across sessions and then under a queue of concurrent questions before estimating service throughput or tail latency.
