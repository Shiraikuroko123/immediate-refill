# Prospective transfer of a measured batch clock

This experiment asks whether a clock measured on homogeneous cached decode windows predicts the physical cost of changing admission on a mixed-length panel. It tests transfer to Qwen2.5-1.5B-Instruct on an A800 in vLLM 0.8.5 V0. The earlier clock used DeepSeek-R1-Distill-Qwen-1.5B. The workloads are constructed and fixed before calibration. The target is the end-to-end time to return all requests in the panel. There are no accuracy, natural traffic, or production service claims.

1. Pin the local model and tokenizer by SHA-256. Use BF16, one GPU, four available slots, identical prompts of 512 tokens, greedy decoding, fixed generated lengths, and disabled prefix caching and chunked prefill. Log the driver, CUDA, GPU and library versions. One warmup block per process is logged and excluded. The runner starts a new output directory for each attempt and preserves incomplete runs. Source hashes cover this protocol, the driver, the runner, and the reused cached-window implementation.
2. Calibrate widths 1, 2, 3 in process A. Each measurement has a 64-step prelude and a timed 96-step window. Shuffle widths within each of eight blocks with seed 3721. Define `c_k` as the across-block median of the per-window mean milliseconds per shared step. Write the measured values, raw calibration hash, predicted contrasts and their decision classes to a new exclusive `prediction.json` before the validation process starts.
3. Set `L=128`. The primary witness uses ordered requests of lengths `(2L,L,L)`. Immediate admission begins with three requests and ends with the long tail at width one. Staged admission begins with two requests and launches the third once the second completes. Their ideal shared-step clock predictions are `L(c3+c1)` and `2L*c2`. The direction control uses `(L,L)` with immediate joint admission versus serial admission. Its predictions are `L*c2` and `2L*c1`. These formulas describe the ideal decode clock. Actual prefill, changing contexts, finish processing, request submission, and scheduling pauses can all influence the transfer error. There is no fitted intercept.
4. Process B reads the sealed prediction and runs 12 validation blocks. Every block runs all four cells once. The four Williams orders in the driver balance arm position and directed adjacency across groups of four blocks. Each arm starts from a drained engine. Use the same request indices and prompts in each pair. Time from before the first `add_request` to the drained engine after CUDA synchronization. Save per-request token hashes and counts, admission and finish events, each step's returned lanes, and its host duration. Report host time spent in steps returning only previously decoded lanes separately from steps returning first tokens. Those diagnostic step times omit some costs included in the primary wall endpoint. Different token values at fixed lengths are disclosed.
5. For each pair define the relative saving from staging as `100*(T_immediate-T_staged)/T_immediate`. For a contrast with predicted absolute value below one percentage point the decision is practical equivalence. Otherwise the decision is the predicted sign. For each contrast report all 12 paired differences, the median and the interval from the third to the tenth order statistic. Under independent repeated blocks with a common continuous median that is a 96.14% median interval. Repeated blocks in one session measure within-session stability. Serial drift can invalidate nominal coverage.
6. A directional prediction passes only when the complete wall interval lies on the predicted side of zero and the observed median differs from the prediction by at most two percentage points. For a predicted equivalence, require the complete wall interval to lie within `[-2%,+2%]` and the same two-point agreement. Both primary and control must pass to describe successful transfer on these workloads. A convincing positive slowdown or saving for the primary witness additionally requires a directional pass. A tie can validate a prediction of limited opportunity. A failed or imprecise witness disallows a general speedup claim and is retained. No block removal, repeated attempts to select a result, early stopping for significance, or adaptive context selection.

The plan requires one A800 session, two engine initializations, 27 calibration windows and 52 validation or warmup panels. The run script defaults to a 30-minute execution limit. Capped output lengths equalize model work across admission policies. The paired scope covers the time needed to execute this finite panel within one model, GPU, prompt length and engine session. No natural stopping, heterogeneous queue, H20 result, or second engine is implied.
